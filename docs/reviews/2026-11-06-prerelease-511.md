# 6.2.6-rc.1 mounting regression: issue #511 and supplied reports

Investigation date: 2026-11-06. Code baseline: `d39c5925` (6.2.6-rc.1).
Sources: [issue #511](https://github.com/Hybrid-Mount/meta-hybrid_mount/issues/511), the four reports supplied by the user, local release history and the installed rustix 1.1.6 source. Raw reports remain local and are not committed.

## Finding and scope

The pre-release has a reproduced extended-attribute read regression. Dependency update `245cf76f` (#508) changes rustix 1.1.5 to 1.1.6. The existing `read_xattr_with` uses a zero-length `getxattr`/`lgetxattr` buffer to query the required length. Rustix 1.1.6 deliberately returns zero initialized bytes from that buffer API; its separate `getxattr_query`/`lgetxattr_query` APIs return the attribute length.

Consequently, a valid nonempty SELinux label is read as an empty vector. That becomes an empty context passed to `lsetfilecon`. Ordinary entry staging logs warnings and continues, but required overlay root metadata cloning propagates the failure and aborts the mount transaction. Changing from tmpfs to ext4 cannot repair the empty label. `tmpfs_xattr_supported` comes from the separate `CONFIG_TMPFS_XATTR` check; its false value does not explain the observed label-write failure on an already mounted ext4 image.

Fix `1ca5e051` already on local dev selects the explicit query APIs and requires rustix >=1.1.6. Keep required directory metadata checks: silently ignoring the label failure would allow incorrectly labeled overlay roots to be published.

The public issue reports Iconify failing after upgrading from 6.2.5 and recovering after downgrade. Its visible log repeatedly shows EINVAL while writing SELinux labels. ## Historical crashes are separate evidence

The Xiaomi report's nested `diag.tar.gz` includes two actual panics, both on **6.12.23**, whereas the collected running kernel is **6.12.69**:

- `last_kmsg`, lines 15688, 15704 and 15723: vendor `hang_detect_thread` deliberately panics after a detected hang.
- `last_kmsg_1`, lines 3297, 3315 and 3345: WLAN `__qdf_bug` / `wma_wait_for_ready_event`, with the CNSS restart call chain.

Neither crash stack establishes a Hybrid Mount callback failure or its timing relative to installing this pre-release. They must not be counted as proof that the current mounting failure panics the kernel. Conversely, the lack of a Hybrid Mount frame does not establish that all indirect interactions are safe.

The Samsung previous-boot kernel log also records an RCU stall; the available sample does not establish its causal relationship to the mount rollback. The confirmed label regression and unresolved black-screen/hang reports remain separate until device evidence connects them.

## Regression verification

Added `utils::linux_tests::xattr_roundtrip_preserves_nonempty_label_bytes`, using a small SELinux-shaped byte string including its trailing NUL in a host `user.*` attribute. It checks both reading and copying without requiring a host SELinux policy.

- RED: in an isolated copy of the committed source, restore only the old length-query implementation. The test fails at the byte equality assertion: actual `[]`, expected the complete label. No capability skip occurred.
- GREEN: current dev passes the test; existing long-attribute and final-symlink-following cases remain covered.
- WSL root `cargo test --workspace --locked`: 598 core unit tests, 3 core CLI tests, 7 notification unit tests, 2 notification CLI tests, 16 xtask tests and 2 xtask notification CLI tests pass (628 total).
- `cargo clippy --workspace --all-targets --locked -- -D warnings`: passes.

This proves the read regression and its local correction, not a completed Android boot/SELinux or Iconify runtime retest. To resolve the two reports without startup failure evidence, retain the failing boot's Hybrid Mount startup log and its `run/state.json` / `run/runtime.json` before a later boot overwrites them. Do not weaken metadata validation or infer a VFS panic from unrelated historical logs.
